# Personas and use cases

| Persona | Job to be done | Success |
| --- | --- | --- |
| Founder or practice lead | Know what is open, what may slip, and who owns the next step | Opens a pipeline and sees current stage, owner, and follow-up for every visible opportunity |
| Operations or workspace admin | Fit the tool to the team's process and onboard users | Configures a template, a custom object, a relationship, a pipeline and a saved view through settings |
| Client or account manager | Record client interactions and follow up on time | Links a contact and company, records meeting notes, and creates a dated task from the record |
| Observer or partner | Review permitted accounts and pipeline status | Can read permitted records and dashboards while write controls are unavailable |

## Core scenarios

1. An admin applies the consulting template, adds an Engagement object with a renewal date, and links it to Company. Existing Company data remains readable after the schema change.
2. An operations admin imports companies. An account manager then creates a contact and a proposal, then moves the proposal to Review. The change appears in its timeline and the configured workflow creates one reminder.
3. A lead opens the Overdue Follow-ups view, filters by owner, and saves a personal variation. The metrics, result list, and export all use the same visibility rules.
4. A manager asks Copilot which visible proposals have had no contact in 14 days. The response links each proposal and describes the date and interaction types used. On request Copilot drafts a follow-up task, previews it, and waits for approval.
5. An admin applies the recruitment template to a separate workspace, links a Candidate to a Position and Interview, and uses the same table, detail, and pipeline components.
6. An admin revokes a teammate's membership while that teammate has a pending Copilot proposal. The user loses workspace access and the proposal cannot execute.
